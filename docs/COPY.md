# 界面文案规范（COPY）

界面上的字只为一件事服务：**让人知道下一步该做什么，以及这个数字能不能信**。
`GLOSSARY.md` 管代码、文档、ADR 里的领域词；本文件管用户能看见的字。两者冲突时以 `GLOSSARY.md` 的领域含义为准，界面可以换一种说法，但必须先写进本文件的「术语双轨」表。

## 三层，三套写法

| 层 | 出现在哪 | 单句上限 | 写法 | 技术词 |
|---|---|---|---|---|
| **L1 首屏 / 空态 / 错误** | `Landing`、三种空态、错误 banner | 25 字 | 先说做什么，再说结果。动词开头，一项一义 | 只允许出现在 `<code>` 路径块里，不进句子 |
| **L2 卡片标题 / 表格 / 图例** | `ui/*Card.tsx` | 35 字 | 名词短语 + 数字，可扫读。副标题只写"这块在比什么" | 允许度量单位（token、积分、pp），不允许字段名 |
| **L3 诊断 / 排查** | 数据体检的溯源行、`title=`、footer | 不限 | 一条一行，保留技术词与原始值 | 全允许，但**必须折叠**，不与 L2 平铺 |

判断标准：一句话如果删掉后用户仍然知道该点哪里、该不该信这个数，就删掉；如果删掉会让用户误判数据缺失或造假，就必须留（可以折叠，不能删）。

## 动作词表（全局只能有一个叫法）

| 用户看到的叫法 | 指什么 | 不再使用 |
|---|---|---|
| **拖入** | 用户把文件夹/文件拖进窗口 | 拖拽、拖进来、丢进来 |
| **选择** | 用户点按钮打开系统选择器 | 选取、浏览 |
| **重扫** | 用已记住的文件夹再读一次（按钮固定叫这个） | 重新扫描、刷新、同步 |
| **读入** | 系统把数据读进内存并出图 | 载入、加载、解析完成 |
| **读取中** | 系统正在读 | 解析中、处理中、加载中 |
| **导入** | 读入一份快照 JSON 文件 | 载入快照、打开快照 |

「已载入」一律改「已读入」：它和「导入」只差一个字，用户分不清哪个是文件夹、哪个是文件。

## 术语双轨

领域词不改名，但首次出现必须跟一句人话，或者干脆不进用户路径。

| 领域词（GLOSSARY） | 界面写法 | 首次出现必须带 |
|---|---|---|
| 端对比 | 端对比 | 「（两边比一比）」 |
| 端 / 两端（泛指两个数据源） | 两边 | 不需要；界面上一律说「两边」，只有指标名「端对比」保留「端」 |
| 数据体检 | 数据体检 | 不需要，三个字已自释 |
| 已知积分 | 已知积分 | 「（有覆盖率的才算）」 |
| 账号消耗下限 | 积分下限 | 「不是"总积分"」 |
| 无记录日 | 无记录日 | 「那天两边都没用，不是数据丢了」 |
| 两条恒等式 | 加总对得上 | 算式：`输入 = 缓存 + 未命中` |
| 快照 | 快照 | 「一个 JSON 文件」 |
| 疑似同项目 | 可能是同一个项目 | 不需要 |
| 自检 | 自检 | 不需要 |

## 保留清单（不许为了"简短"改掉）

- **数据体检**、**无记录日**、**已知积分**、**账号消耗下限**、**端对比**、**快照**、**总账**——这些是准确且有辨识度的造词，换成"数据质量报告""缺失天""总积分"会变长或变错。
- 所有**限定条件**：「只是下限」「不按比例外推」「不换算人民币」「不做插值」。它们防的是用户拿数字去对账后认为你在骗人。
- 路径块里的 `history/**/index.json`、`projects/**/*.jsonl`——这是让用户核对"有没有选对文件夹"的定位信息。

## 禁用词（L1/L2 一律不许出现）

`句柄`、`文件框`、`归一`、`恒等式`、`usage`、`requests[]`、`jsonl`、`vscdb`、`selectedModelId`、`ai-title`、`fail`、`ms`、`索引`、`元数据`、`在途`、`口径`、`对拍`、`聚合`、`切片`

替换规则：

| 禁用 | 换成 |
|---|---|
| 目录句柄 / 没有可复用的句柄 | 没记住文件夹 |
| 文件框（`<input webkitdirectory>`） | 窗口选择 |
| 归一后同 key 不同原串 | 路径不同但看着是同一个项目 |
| 恒等式 fail | 加总对不上 |
| 在途跳过 | 写到一半的记录 |
| usage 全零回落 | 记录里全是 0 |
| 解析 / 解析中 | 读取 / 读取中 |
| 口径限制 | 这类数字本身的上限 |

## 已裁决的替换（后续别再改回去）

| 原文 | 改成 | 为什么 |
|---|---|---|
| 50% 分位 | 中位数 | 同一个数，后者不用查统计书 |
| 窗口覆盖率 | 有记录的天占 X | 自造词，没人知道"窗口"指哪一段 |
| 对比上一个等长窗口 | 对比上一个同样长的区间 | 同上 |
| 归一化 cwd / hash 聚合 | 按文件夹路径归类 / 按记录里的项目标识归类 | 实现细节，用户不需要 |
| 恒等式 fail / 在途跳过 / 无 credit | 加总对不上 / 写到一半 / 没有积分字段 | 前三个只有作者看得懂 |
| 请求级 model / 会话级 selectedModelId | 每次请求都记模型 / 只记在会话上 | 字段名不进句子 |
| 覆盖 X% 请求 | X% 请求有积分 | 同样字数，主谓清楚 |

## 折叠规矩

L3 诊断信息不进默认视图，用 `<details className="health-more">` 收起，`<summary>` 里要先回答用户最想问的那句（例：「已知缺口 5 条：不是 bug，是数据本身记不全」）。
能靠 `title=` 说明的单个值（索引数、元数据数、字段名）优先用 `title`，不为了它多开一层折叠。

## 五条检查（第 1–3 条已脚本化）

```bash
npm run lint:copy    # 扫 src/App.tsx 与 src/ui/*.tsx 里含中文的可见文案
```

退出码 `1` = 有禁用词（阻断），只有超长提示时为 `0`。脚本只取 JSX 文本与字符串字面量，所以注释、类型名和 `<code>` 里的路径块不会误报；新增禁用词要同时改 `scripts/lint-copy.ts` 与本文件。

1. **句长**：L1 单句 ≤ 25 字，L2 ≤ 35 字。按「。；，」切分后逐句量。
2. **术语**：L1/L2 里出现上表禁用词即失败；领域词首次出现未带解释也失败。
3. **动作**：同一动作出现第二种叫法即失败（`载入/导入/扫描/拖` 混用是历史问题）。
4. **一问一答**：新用户看首屏 5 秒后，能否说出"我要把哪个文件夹拖进来"。2–3 人复述一致才算过——**不靠模型自评**。
5. **不许删限定**：改动 diff 里如果删掉了"下限 / 不外推 / 不换算 / 不插值"中的任何一个，必须人工复核。

## 为什么是这套规矩

借自 `pbakaus/impeccable` 的只有流程，不是它的文案内容（它的 `clarify` 是英文语境，规则引擎也只查字体/对比度/间距，不含中文可读性）：

- **单一意图**：一次只做一类改动（先删，再换词，最后调语气），否则改完不知道哪一步起了作用；
- **先固化再动手**：`PRODUCT.md`/`DESIGN.md` → 本文件，防止后续批次各自发明说法；
- **分级 + 确定性规则**：它的 62 条规则 → 上面五条检查，把"别写出烂文案"变成能跑的规矩，而不是每次靠人记得。
