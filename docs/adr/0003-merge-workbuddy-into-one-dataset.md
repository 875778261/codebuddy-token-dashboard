# ADR 0003：WorkBuddy 作为一个源并入同一份 Dataset，合并必须归一化，积分只能是「账号消耗下限」

- 状态：已采纳
- 日期：2026-10-29
- 相关：`docs/workbuddy-data-sources.md`（§0 结论、§2.5 积分四路、§9 跨源合并）

## 背景

看板原本只服务 CodeBuddy IDE。WorkBuddy 的本地数据结构已勘察完毕（`~/.workbuddy/projects/**/*.jsonl`，逐请求 usage 齐全），目标是把它的数据**加载进来与 CodeBuddy 合并成一份统计**，而不是做成第二个独立看板或加一个"数据源筛选器"。

两条来自用户的事实决定了口径，且**无法用代码消除**：

1. **多 agent 切换使用**：用户会在多个 AI 工具间切换，某个产品某天没有记录是常态，不代表数据丢失。原报告把它记为「缺失 25 天」并暗示会话被删，归因是错的。
2. **积分账户共用**：CodeBuddy 与 WorkBuddy 扣的是同一个积分池。任何单产品的 `Σcredit` 都只是账号账单的一部分，两个数字相加更接近真值但仍小于真值。

实测（2026-10-29，只读探针）：两源 token 用量零重叠；项目 cwd 写法不同（CodeBuddy 正斜杠、WorkBuddy 反斜杠、WorkBuddy db 大写盘符），**原始字符串相等的项目 0 个**，按末段名配对仅 1 个交叠；模型名 5/7 跨源同名。

## 决策

**1. 单一 Dataset，单一数字。** `Dataset` 增加 `source` 维度，`SessionRecord` 增加 `source` / `isSubAgent`，新增纯函数 `mergeDatasets()`。`aggregate.ts` 与所有图表**不改聚合逻辑**即可吃合并结果。`source` 只用于追溯与数据体检，**不作为统计维度**，UI 不提供"只看某一源"的切换。

**2. 合并必须先归一化，三处，缺一不可。**

- **项目路径**：`\`→`/`、去尾斜杠；**大小写绝不归一**（用户裁定：宁可裂成两行也绝不误并）。分隔符统一不属于大小写范畴，且不可能造成误并。
- **模型名**：请求级 `r.model`（WorkBuddy 自带）优先，回落会话级 `session.modelId`（CodeBuddy）。沿用 `glm-5.2-x → glm-5.2`。不为此去解析 CodeBuddy 的 `messages/*.json`（14,534 个文件）。
- **会话 ID**：一律加源前缀 `codebuddy:` / `workbuddy:`。两源都是裸 UUID，现有解析器对同 ID 会话会**静默合并**，这是不可逆的错误。

归一后出现「同 key 不同原串」时，计入 `selfCheck.suspectedDuplicateProjects` 并在体检页呈现，**由人判断，不由程序自动合并**。

**3. 积分只做一个数字，且只能叫「已知积分」。** 覆盖率按**请求数加权**（两源共同计入分母），禁止把两个百分比相加或取平均。不得按比例外推到账号账单。

**4. `missingDays` 降级为「无记录日」**：两源皆无记录的日子，中性留白，不画缺口告警。

**5. 首版不读 `workbuddy.db`。** 请求级 `model` / `cwd` / `credit` 全在 jsonl 里，db 只把标题覆盖从 63% 提到 100%。通用 SQLite 行解码器（`sessions` 表 43 列）作为后续增强，不进首个里程碑。

## 考虑过的替代方案

- **两套独立路径 + UI 切换**：被否。用户的目标是"一份总账"，切换等于把合并退回去；且项目榜永远无法把同一项目的两个工具用量放在一起。
- **项目路径全量小写归一**：被否（用户裁定）。win32 文件系统大小写不敏感，理论上小写化不会误并，但用户优先要「绝不误并」这一更强保证；代价是万一上游出现大小写不同的同一路径，项目榜会裂开——由体检告警兜住。
- **项目榜按目录名（cwd 末段）合并**：被否。`D:/a/util` 与 `D:/b/util` 会被误并成一条，这正是要避免的假合并。
- **积分不展示**：被否。共用账户下"合计 + 明确的下限标注"仍有对账价值，比不展示更有用。

## 后果

- 正向：一个入口看全部 AI 用量；项目榜是**并集**（实测 25 个项目），能回答"这个项目我用了 CodeBuddy 还是 WorkBuddy"；空档问题基本自愈（并集 ≥ 77/102 天）。
- 代价：积分永远对不上官方账单，差额必须在 UI 上解释，不能靠算法消除；CodeBuddy 侧模型归属仍是会话级，模型榜里「未记录模型」桶会明显变大。
- 约束：`Σcredit` 的文案不得出现「总积分」；合并层不得再做跨源去重（两源 token 零重叠，跨源"去重"只会掩盖单源解析 bug）。
