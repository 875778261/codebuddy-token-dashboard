# ADR 0006：三源两端——源是数据根，端才是比较单位

- 状态：已采纳
- 日期：2026-11-20
- 相关：`docs/adr/0004-source-slices-and-compare.md`（扩展其决策）、`docs/codebuddy-cli-data-sources.md`、`GLOSSARY.md`

## 背景

`GLOSSARY.md` 把「数据源」定义为**一个产品在本机落盘的用量数据根**，`SourceId` 只有 `codebuddy` 与 `workbuddy`，端对比是二元三层（量差 / 同模型效率差 / 节奏差）。

CodeBuddy CLI 带来了第二个根：`~/.codebuddy`（日志）与 `%LOCALAPPDATA%\CodeBuddyExtension\Data`（history）**互不相干**——格式不同、保留窗口不同、积分覆盖率也不同。三选一：

- **A. 三源平权**：端对比从二元改成 N 元或可切换配对。能直接比「同一产品的 IDE vs CLI」，但端对比卡要重写，"共用账户"的语义更绕。
- **B. 两层**：源=形态（3 个），端=产品（2 个）。
- **C. 并入 `codebuddy` 源**，内部加 `form` 字段。最省事，但一个 `SourceSummary` 里混两种格式与两套保留窗口，「该端已知积分 / 字段覆盖缺口 / 新鲜度」全部说不清。

## 决策

**采用 B：源与端分层。**

1. `SourceId` 扩为 `codebuddy | codebuddy-cli | workbuddy`；`Source` 的定义不变——仍是「一个数据根」。同一产品可以拥有多个源。
2. 新增 `EndId = codebuddy | workbuddy` 与 `END_OF_SOURCE` 映射，`sourcesOfEnd()` 是唯一归组入口。**端对比、账号消耗下限只在端层成立**；源切片视图仍在源层。
3. 端对比的内部实现不新增聚合函数：`aggregatesByEnd()` 先按端裁一遍 `dataset.sessions`，再调同一个 `aggregate()`（沿用 ADR 0004 的「唯一一份聚合实现」）。
4. 端内构成只露一行占比（`CodeBuddy 端内：IDE xx% / CLI yy%`），不把三层对比扩成 N 元矩阵。
5. 源的固定配色收口到 `ui/theme.ts` 的 `sourceColor()`：CodeBuddy=0、WorkBuddy=1 不变，CLI=2，避免各卡片自己排色导致语义漂移。

**明确禁止**：为 CLI 新增第二套聚合、第二份 Dataset 结构，或把 ``aggregate()`` 拆成「按端」与「按源」两个实现。

## 后果

- 端对比卡与「账号消耗下限」的文案、指标一件不用改；新增成本是一个常量映射 + 一处渲染。
- 新增源时必须同时落位 `END_OF_SOURCE`，否则该源用量不进端对比（这是一处显式的手工同步点，用类型 `Record<SourceId, EndId>` 保证编译期不漏）。
- 「端内构成」只给占比与一句说明，端的效率差仍以端为单位，不回答「IDE 与 CLI 谁更省」——那需要另一次实验设计。

## 修订（2026-11-20）：端层会吞掉源缺口，补一层「数据完整度」

端层上线后立刻出现一个副作用：只读入 CLI 时，CodeBuddy 端已经「能比」，端对比的空态提示随之消失——「IDE 那份还没读」这个事实没有任何地方会说。

裁定：**完整性提示必须两级**，判定收口在 `src/core/completeness.ts` 一处。

1. 源级：逐源给出已读入 / 未读入（判定见 GLOSSARY「已读入」：有数据才算，有句柄但 0 条恰是路径错了）。
2. 端级：在源级结论上再说「能不能比」与「端内缺谁」。
3. 允许「我没有这个源」（GLOSSARY「已声明没有」），否则只用 CLI 的人会被永久打扰；标记只影响提示，不进数据、不进快照。
4. 快照与示例不提示缺源：那两条路径下的「缺」是选择，不是遗漏。
5. 提示落两处：顶栏一行（结论，只在本机扫描来源下出现）、数据体检卡一行（端结论）。
6. **路径清单单独成条**，放在 KPI 下面（`ui/MissingSources.tsx`），一行一个源、带复制与「我没有」。它属于"便利"而不是"告警"，所以快照与示例下照常显示；已声明没有的源不再贴路径，但条内保留恢复入口。
