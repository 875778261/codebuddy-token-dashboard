# ADR 0005：国内入口只用 EdgeOne Pages，不提供 Gitee 托管与源码镜像

- 状态：已采纳（2026-10-31 修订：EdgeOne 默认域名实测为 3 小时限时预览，不构成常驻入口）
- 日期：2026-10-31
- 相关：`docs/deploy.md`、`README.md`「部署」、`.github/workflows/pages.yml`

## 背景

需求是「让页面也能自动部署到 Gitee，国内用 Gitee 更稳」。核查 Gitee 现状（2026-10-31）：

- Gitee 反馈区（`oschina/git-osc`）官方答复：「由于不可抗原因，Pages 服务已经下线，暂无具体计划再次上线」（2024-05）；
- 服务页提示语：「因服务维护调整，Gitee Pages 暂停提供服务」；
- `gitee.io` 首页：「Gitee Pages 服务已下线，恢复时间暂无计划」。

即**不存在可自动部署的 `*.gitee.io` 托管目标**，为它写任何 workflow 都不会有产出。

需求背后实际是两件事，必须分开看：

1. 国内无代理**访问页面**稳定（现状：`*.workers.dev` 被 SNI 阻断，`*.github.io` 约 30s，`*.pages.dev` 2~4s）；
2. 国内协作者 **`git clone`** 快。

## 决策

**1. 不提供 Gitee Pages 入口，也不为它维护 workflow。** 事实写进 `docs/deploy.md`，避免后来者照着仍在流传的旧教程折腾。

**2. 国内托管入口用 EdgeOne Pages**，源为 GitHub 仓库。控制台关联 Git 仓库 → `npm run build` → 产物目录 `dist` → push 即重建。该步在控制台完成，仓库内无需改动。

**但默认域名不构成常驻入口。** 加速区域含中国大陆时，`*.edgeone.cool` 必须用系统生成的预览链接访问，链接带 `eo_token` / `eo_time` 签名、有效期 3 小时，超时或裸链接一律 401（2026-10-31 实测：带参 200，换机去参 401）。这是区域合规策略，控制台无开关。因此 EdgeOne 目前只能是临时预览；成为常驻入口的前提是先有**已备案的自定义域名**，或删项目重建并选「全球（不含中国大陆）」（加速区域创建后不可自助修改，且该区域境内访问同样受限）。在有备案域名之前，不要把它写进 README 入口表。

**3. 暂不做 Gitee 源码镜像。** 镜像只解决 `git clone` 慢，不解决页面访问，在 Pages 下线的前提下收益有限；Gitee 侧还要求仓库公开、令牌可直接推送，属于额外的凭据维护成本。将来确有需要时再补，勿提前铺路。

## 考虑过的替代方案

- **`gitee-pages-action` 等第三方 action**：否。目标服务已下线，无对象可刷新；且需要在 GitHub Secrets 存 Gitee 账号密码、走非公开接口，与仓库「不引入不可审计凭据」的取向冲突。
- **Gitee 源码镜像（Actions 推或 Gitee 定时拉）**：暂缓，理由见决策 3。
- **阿里云 OSS / 腾讯云 COS**：大陆可达性最好，但默认域名对 HTML 强制下载，必须绑已备案域名，超出「零成本、自助开通」的边界。
- **把 `dist` 推到独立分支再交给第三方托管**：前提是对方有 Pages，已被事实否决；GitHub Pages 侧现有 `pages.yml` 已覆盖该形态。

## 后果

- 正向：国内入口不再押在一个已下线的服务上，也没有多余的镜像链路与凭据需要维护。
- 代价：EdgeOne 接入属于控制台操作，无法写进 CI；默认域名不可长期访问，国内常驻入口仍缺一个已备案域名，短期内这张表上只有境外三条链路。
- 约束：任何「国内可访问」的新入口，都必须先说明**是否免备案、是否 push 即更新**，否则不进 README 部署表。
